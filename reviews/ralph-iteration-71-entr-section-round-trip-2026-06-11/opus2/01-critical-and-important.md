# Critical & Important Findings

## Critical

**None.** The landed code is correct, internally consistent, and tested end-to-end. The
byte layout matches the live device, version gating works, and the v1/v2 coexistence is
proven loud on misuse.

## Important (non-blocking — both are follow-up beads, NOT defects in this branch)

### I1 — The v2-split→`device.restore` version-mismatch seam is undocumented at the call site

- **File:** `crates/dh-snapshot/src/dhsnap.rs:407-414` (`EntrSectionV2::device_regs`)
- **Severity:** Important (forward-looking; affects qmp, which is unwritten)

**The trap (verified by experiment).** `EntrSectionV2` lives at section version **2**, but
the pv-entropy DEVICE's `restore(bytes, sec_version)` only accepts its OWN
`SECTION_VERSION = 1` (`crates/dh-devices/src/entropy.rs:43,174-177`). I confirmed in a
scratch test that `device.restore(regs, 2)` returns `Err(RestoreError)` while
`device.restore(regs, 1)` succeeds. So when the qmp restore engine splits a v2 ENTR
section, it must call:

```rust
let v2 = EntrSectionV2::decode(sec.contents, sec.sec_version)?; // sec_version == 2
entropy.restore(EntropyState { seed: v2.seed, stream: v2.stream, word_pos: v2.word_pos });
device.restore(&v2.device_regs(), device.section_version())?;   // == 1, NOT sec.sec_version (2)
```

The naive (and tempting) mistake is `device.restore(&v2.device_regs(), sec.sec_version)`
— passing the ENTR **section** version 2 — which yields `RestoreError` at restore time,
on the hardware-gated path, far from this code.

**Why it matters now.** The `device_regs()` doc comment says *"in the exact
`DetDevice::restore` layout"* — which correctly describes the BYTES but is silent on the
VERSION, the one thing that will bite the engine author. The whole point of the v2 design
is that one section carries two version domains; the doc must name the split explicitly.

**Fix (one comment, this file or follow-up):**

```rust
    /// The device-reg half, in the exact `DetDevice::restore` layout.
    ///
    /// SEAM (qmp restore): pass these bytes to `device.restore(regs, V)` with
    /// the DEVICE's `section_version()` (== 1) — NOT this ENTR section's
    /// version (2). The pv-entropy device REJECTS version 2 with RestoreError
    /// (entropy.rs SECTION_VERSION); the two version domains are deliberately
    /// distinct. Mirror: `prng()` feeds `DetEntropy::restore`.
    pub fn device_regs(&self) -> [u8; 16] {
```

**Note:** No code in the repo yet consumes `EntrSectionV2` outside the test — the qmp
engine (the only blocked-on dependency, now unblocked) is the future caller. So this is
correctly *documentation for the next iteration*, not a bug in the current diff. File it
on the **qmp bead** or a tiny doc bead so the version split is impossible to miss.

### I2 — `rand_chacha` is caret-ranged with no known-answer pin; a stream-semantics drift would not fail loudly

- **Files:** `crates/dh-devices/Cargo.toml:11` (`rand_chacha = { version = "0.3", ... }`),
  `Cargo.lock` (resolved `0.3.1`), `crates/dh-devices/src/entropy.rs` (no KAT)
- **Severity:** Important (latent; correctness-of-determinism risk on dependency upgrade)

**Finding.** The ENTR resume guarantee rests entirely on `rand_chacha`'s
`get_seed`/`get_stream`/`get_word_pos` + `set_*` producing a byte-identical stream across
versions. The manifest pins only the major-minor caret `"0.3"`; `Cargo.lock` currently
resolves `0.3.1`. A `cargo update` to a hypothetical `0.3.2` (or anyone regenerating the
lock) that changed word-position quantization or stream indexing would **silently** break
fork-and-replay — the existing tests only assert *self-consistency* (snapshot→restore in
the same binary), which stays green even if the absolute byte stream shifts. I grepped
`crates/dh-devices/tests` and the whole `crates/` tree: **no known-answer / seed→bytes
vector exists anywhere** (the golden DHILOG/DHSNAP fixtures pin container framing and
digests, never raw PRNG output bytes).

**Recommended fix (a known-answer test).** Add to `entropy.rs` `tests` — uses the values
I generated by experiment on the pinned `0.3.1`:

```rust
#[test]
fn prng_known_answer_pins_rand_chacha_stream() {
    // KAT: catches a rand_chacha upgrade that changes stream semantics.
    // If this fails after a dep bump, ENTR resume is silently broken —
    // do NOT "fix" the expected bytes; investigate the upgrade.
    let mut e = DetEntropy::from_seed([0x42; 32]);
    let mut out = [0u8; 32];
    e.fill(&mut out);
    assert_eq!(
        out,
        [0xa4,0xdd,0xf3,0x1f,0x7f,0x32,0xba,0x69,0x6f,0x14,0xce,0x50,0xec,0xf3,0xf2,0x1e,
         0x3e,0x10,0x0e,0x83,0xbd,0xf4,0x79,0x66,0xe7,0xb0,0x74,0x68,0xe9,0x50,0x0b,0x6e],
        "rand_chacha stream drifted (seed=[0x42;32], stream=0)"
    );
    // also pin a nonzero stream to cover set_stream:
    let mut e7 = DetEntropy::restore(EntropyState { seed: [0x42;32], stream: 7, word_pos: 0 });
    let mut o7 = [0u8; 32];
    e7.fill(&mut o7);
    assert_eq!(
        o7,
        [0xbf,0xd3,0x20,0x81,0x45,0xf9,0x42,0x96,0xda,0xad,0xaa,0xa4,0x0c,0x67,0x7e,0xf8,
         0x9d,0x75,0x31,0x2e,0x77,0xd0,0xbd,0x23,0xb1,0x15,0x05,0x8d,0x4e,0x9d,0x7e,0x18],
        "rand_chacha set_stream semantics drifted (stream=7)"
    );
}
```

(Optionally also tighten the manifest to `=0.3.1` so the lock can't float, though the KAT
is the louder guard and survives lock regeneration.) This is *add-worthy follow-up*, not a
blocker for merging this branch.
