## Verification performed (against reality, not the diff's claims)

- **Proto wire numbers** confirmed in `dh-proto` codegen + its own pin test
  (`crates/dh-proto/src/lib.rs:full_surface_message_shapes`): `StopReason` 0..=7,
  `SlotState` `Empty=1 / PausedS=2 / Running=3 / Frozen=4 / FaultedS=5`. The proto_map pins match.
- **Domain discriminants** confirmed: `dh-vmm` `SlotState` `Empty=0 Running=1 Paused=2 Frozen=3
  Faulted=4` (`crates/dh-vmm/src/lib.rs:42`); `runctl::StopReason` has 5 variants, no `Faulted`,
  no `NextSdkEvent` (`crates/dh-vmm/src/runctl.rs:48`). The "4 lies / Paused coincides" claim is
  arithmetically correct.
- **prost derive surface**: generated enums derive `PartialEq, Eq` and `#[repr(i32)]`
  (`::prost::Enumeration`), so the `assert_eq!` on decoded variants is valid. `TryFrom<i32>` is
  generated by the derive and is **closed** — empirically `StopReason::try_from(300)` and
  `try_from(8)` both `Err` (probed against prost 0.13.5, then reverted). This is load-bearing for
  the u8-fit finding below.
- **Golden fixtures**: `crates/dh-inputlog/tests/golden.rs` seals kitchen-sink with
  `stop_reason: 2` (GOAL_SATISFIED) and minimal with `stop_reason: 0` (STOP_UNSPECIFIED); the
  frozen `.dhilog` bytes carry those exact values (golden.rs already asserts `r.end() == (2, …)`).
- **`reader::end()`**: `crates/dh-inputlog/src/reader.rs:310` does `records().last().unwrap()`; safe
  because `LogReader::parse` rejects unsealed logs up front with `ReadError::NotSealed`
  (reader.rs:375). Both new fixtures are sealed — no panic path reachable from this test.
- **aarch64 cross-clippy**: ran
  `cargo clippy -p dh-inputlog -p dh-proto -p dh-worker --all-targets --target
  aarch64-unknown-linux-gnu -- -D warnings` (clang + extracted arm64 headers) — **clean**. The new
  `dh-proto` dev-dep compiles under the cross lane because the vendored-protoc build script runs on
  the HOST (`protoc_bin_vendored::protoc_bin_path()` is host-arch); tonic-build emits only Rust.
  No target-specific build-script hazard.
- **Tests run green**: both `stop_reason_mirror` tests and both `proto_map` tests pass on the
  x86_64 host. No dead-code warnings from the two unused `pub` fns (pub-in-lib suppresses them).

## Verdict

**Approve with one Important finding.** The coupling the bead asked for is now a checked fact, the
wire-number pins are correct and well-targeted, and the cross-arch lane genuinely passes for the
reason claimed. The one substantive issue is a silent gap in the u8-fit guarantee: the `0..=255`
scan cannot observe a future proto variant numbered ≥256, and the `count == 8` pin does not close
that gap (a 9th variant at 300 keeps the in-range count at 8 while not fitting a u8). Everything
else is suggestion-grade. Two items of the bead's *extended* scope (the `as i32` grep-ban,
`runctl::StopReason::Faulted`) are explicitly deferred, not silently dropped — see scope notes.
