# Findings

1. [P1] Production `Run` does not service the new lAPIC at all.
   The branch wires LAPIC MMIO/MSR handling into `DeviceRail::service_exit` and replay, but the worker's production detchannel wrapper has its own dispatch. `service_exit_with_detchannel` sends every MMIO read/write to the bus at `crates/dh-worker/src/service.rs:2154` and `crates/dh-worker/src/service.rs:2160`, and all `X86Rdmsr`/`X86Wrmsr` exits fall into `unexpected exit` at `crates/dh-worker/src/service.rs:2168`. That wrapper is what `Run` calls at `crates/dh-worker/src/service.rs:3522`. A Linux access to `0xfee00000` or `IA32_APIC_BASE` in dh-workerd will still fail instead of using `LocalApic`. Add the LAPIC arms to this wrapper before the bus/default cases, or factor one shared LAPIC-first exit service used by recording, replay, and the worker detchannel path.

2. [P1] lAPIC state is reset between worker `Run` calls.
   `DeviceRail::new` always constructs `LocalApic::new()` at `crates/dh-vmm/src/recording.rs:89` to `crates/dh-vmm/src/recording.rs:93`. The production run path creates a fresh rail for each run at `crates/dh-worker/src/service.rs:3501`, then writes back only `bus`, `entropy`, and `log` at `crates/dh-worker/src/service.rs:3695` to `crates/dh-worker/src/service.rs:3697`. The mutable APIC registers written in `crates/dh-vmm/src/lapic.rs:239` to `crates/dh-vmm/src/lapic.rs:267` are dropped. Once finding 1 is fixed, Linux APIC setup in one run can be forgotten before the next run of the same slot/segment. Persist the LAPIC in `SlotRuntime` or move it into a snapshotted device owner, and seed subsequent rails from that state.

3. [P1] lAPIC state is not snapshotted or restored.
   The new model contains guest-visible mutable state, including TPR, SVR, LVTs, IRR/ISR, ESR, ICR, and APIC base. Snapshot capture still writes an empty LAPC section at `crates/dh-worker/src/snapshot_engine.rs:295` to `crates/dh-worker/src/snapshot_engine.rs:298`, and restore explicitly accepts only empty LAPC at `crates/dh-worker/src/restore_engine.rs:303` to `crates/dh-worker/src/restore_engine.rs:313`. Bisection checkpoint capture also passes only bus and entropy at `crates/dh-worker/src/service.rs:3609`, so checkpoints cannot carry LAPIC state either. A snapshot after APIC setup will restore with a default `LocalApic`, breaking replay/fork transparency. Either encode/decode `LocalApic` in LAPC and plumb it through runtime, restore, fork, and replay, or reject any stateful LAPIC write until the LAPC schema lands.

4. [P2] ICR writes are silently accepted without modeling delivery.
   `REG_ICR_LOW` and `REG_ICR_HIGH` are stored as plain values at `crates/dh-vmm/src/lapic.rs:248` and `crates/dh-vmm/src/lapic.rs:249`. ICR writes are side-effectful: INIT/SIPI/IPI/self-IPI delivery cannot be acknowledged as a no-op without hiding unsupported interrupt behavior from the guest. Fail closed for unsupported ICR delivery modes/destinations, or implement the deterministic subset and add tests for the accepted cases.
