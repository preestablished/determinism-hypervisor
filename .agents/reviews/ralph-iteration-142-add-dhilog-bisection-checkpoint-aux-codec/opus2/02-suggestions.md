# 02-suggestions.md
- [reader_validation.rs](/home/infra-admin/git/preestablished/determinism-hypervisor/crates/dh-inputlog/tests/reader_validation.rs:699): The “golden bytes” checkpoint test still routes payload construction through `bisection_checkpoint_payload`, the same helper used by other tests. It catches current offset mistakes, but future coordinated edits to the helper and codec could still launder layout drift. Consider adding literal byte assertions for the checkpoint payload offsets, especially `[0..8]`, `[8..40]`, `[40..48]`, and `[48..56]`.

- [reader.rs](/home/infra-admin/git/preestablished/determinism-hypervisor/crates/dh-inputlog/src/reader.rs:500): Decide whether `max_covered_gap` is purely verifier policy or a codec-level consistency invariant. If the verifier is expected to trust this payload field, the reader should eventually cross-check it against adjacent checkpoint icounts; if not, a short comment would prevent future readers from treating it as already validated evidence.
