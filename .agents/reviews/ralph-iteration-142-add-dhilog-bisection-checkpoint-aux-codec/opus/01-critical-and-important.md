# 01-critical-and-important.md
- Important - `crates/dh-inputlog/src/reader.rs:667`, `crates/dh-inputlog/src/dhilog.rs:354`: `BISECTION_CHECKPOINT` duplicates the record header `icount` inside the payload, and the writer always stores the same value, but the reader does not validate that these two fields agree. A malformed sealed log can pass `LogReader::parse()` with `rec.icount() != checkpoint_icount`, leaving downstream bisection code with conflicting checkpoint positions. Suggested fix: pass the record `icount` into the kind-specific validation, or add a post-parse record check, and reject mismatches with `BadPayloadLayout` or a dedicated `ReadError`. Add a test that hand-frames a checkpoint with header icount `10` and payload checkpoint icount `11` and expects rejection.
